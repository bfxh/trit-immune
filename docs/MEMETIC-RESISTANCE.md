# 模因污染与抗干扰：从太空辐照硬化到裁决账本的免疫架构

> 一句话：**太空抗干扰工程与裁决账本的抗污染问题是同构的**——都是"腐蚀
> 在累积中发生"。太空用三模冗余/纠错码/周期刷新对抗单粒子翻转；裁决账本
> 用证据分级/隔离检疫/人工复核对抗模因注入。本文调研两个领域，提出三个
> 迁移想法，其中 **Belnap 四值 = 模因矛盾检测器** 是本轮的核心产出。

## 一、问题的同构性

| 维度 | 太空（自然腐蚀） | 账本（对抗注入） |
|---|---|---|
| 腐蚀源 | 高能粒子（SEU 单粒子翻转、TID 总剂量、闩锁） | 投毒数据、提示注入、伪造发现、叙事植入 |
| 腐蚀形态 | 位翻转（可恢复） vs 闩锁（破坏性） | 假 -1（冤枉）vs 假 +1（洗白） |
| 累积性 | 翻转随暴露时间累积 | 污染随传播边累积 |
| 检测 | ECC 校验、读回比对 | 哈希链、溯源、**矛盾检测** |
| 修复 | 刷新（scrubbing）、TMR 表决 | 复核（人工裁决）、反熵同步 |
| 哲学差异 | **无意图**——粒子不针对你 | **有意图**——攻击者适应你的防御 |

哲学差异是本质的：太空防御可以假设腐蚀**与内容无关**（任何位都可能翻），
所以 TMR 的多数票有效；对抗注入**与内容强相关**（攻击者专挑验证薄弱的
边），所以单纯冗余不够——需要**证据分级 + 语义矛盾检测**。这条分界线
决定了两个领域各自的工具箱。

## 二、太空抗干扰工程调研（可迁移的四个机制）

1. **三模冗余（TMR）**：1 位 → 3 位复制 + 多数表决（经典形态；NASA Berg
   2016 综述 Block-TMR / Selective-TMR 变体——按故障概率选择性加固）。
2. **纠错码 + 刷新（scrubbing）**：ECC 校验可纠 1 位错；配置存储**周期性
   读回刷新**——错误在累积成失效前被清掉。
3. **故障隔离**：闩锁（破坏性 SEU）与可恢复翻转分类处理；Block-TMR 把
   故障域切小（一块翻转不污染邻块）。
4. **抗干扰通信面**：扩频/跳频（把信号藏进噪声底）、定向天线零陷、
   交叉链路路由（绕过被干扰节点）。

## 三、模因污染的分类学（认知安全侧）

- **训练期投毒**：数据注入/标签投毒/clean-label 投毒（污染数据看起来合法）；
- **推理期注入**：间接提示注入（邮件/文档/网页携带指令）——Blackbird.AI
  称之为"污染源"：智能体的行为被污染内容改写；
- **叙事传播**：模因的适合度 = 重复度 × 置信度 × 情绪显著性——三者越高
  传播越快，且**不需要为真**；
- **检测共识**：无单一签名——依赖溯源控制、数据集审计、传播监控。

## 四、自己的想法（三个迁移）

### 想法一：Belnap 四值 = 模因矛盾检测器

三值账本已有 Belnap 四值（T/F/B/N，B = 矛盾）做证据合并。**模因污染的
传播恰好制造矛盾**：一个被污染的 `-1`（伪造发现）经跨仓边传播到下游，
遇到下游自己干净判定的 `+1` → 合并结果 `B`（既真又假）→ **`needs_review`
自动立起**。

这就是把"叙事矛盾"变成机器可检测的信号：污染者要让伪造判定**自洽地**
通过整条传播链，必须同时污染溯源哈希、伪造可复现证据、且与下游独立
判定不冲突——三道墙中任何一道独立成立。B4 的冲突不是错误状态，是
**模因矛盾的告警器**——这是四值逻辑在安全域的第二个用途（第一个是
签名篡改检测）。

### 想法二：复核 = memory scrubbing

FPGA 配置存储的刷新周期：错误位在累积成系统性失效前被周期性清除。
映射到账本：**Claimed（纯声称）节点 = 未刷新的配置位**——它们是污染
的驻留面。N1 人工复核周期 = scrubbing 周期：每轮复核把 Claimed 升级为
Reproduced/Adjudicated 或降级清除。`verified_ratio`（已验证比例）= 刷新
覆盖率。可复算的推论：**verified_ratio 的下降速率 = 污染注入速率的
下界估计**——不需要抓住攻击者，从覆盖率曲线就能看见污染的存在。

### 想法三：裁决 TMR（多扫描器表决算子）

太空 TMR 的三副本多数票，迁移到判定层：**三个独立来源的扫描器**对同一
样本各产三值判定，表决合成一个账本节点。语义分析（与 Kleene AND/OR 的
差异）：多数票对三值不是 Kleene——`(T, U, U)` 多数票无多数 → 应为 `U`
（弃权传染），而 Kleene AND(T,U,U) = U ✓ 但 AND(U,U,U)=U、OR(U,U,U)=U
——三值下"无多数"天然落在 U，**多数票算子 = 按出现次数排序取众数，
平票取 U**（已在 trit-wspace 的 `merge_tasks` 投票里实现过同款：票和取
符号、平票保留基准）。新贡献：把该算子提升为账本的**多扫描器判定合成**
原语——不同引擎（YARA/自研/商用）各出三值判定，TMR 表决后入账；单引擎
被投毒（误报率抬高）被另外两票压制。**这是"扫描器永不 +1"的工程化强化：
单个扫描器的污染无法入账。**

## 五、与三线系统的映射

| 太空机制 | 账本现有实现 | 差距 |
|---|---|---|
| TMR 多数表决 | `merge_tasks` 投票（wspace） | 未提升为**判定层**通用算子（想法三） |
| ECC 哈希链 | 追加式日志 + sha256 链 | ✅ 已有 |
| 周期刷新 | N1 人工复核（手动） | 未周期化：verified_ratio 曲线未监控（想法二） |
| 隔离（Block-TMR 故障域） | 外部输入自动隔离 | ✅ 已有 |
| 抗干扰路由 | 跨仓传播边 | 污染边无**绕行/降权**机制（B 检测后未自动降权） |
| 矛盾检测 | Belnap B 传播 | 未把 B 显式建模为**模因告警**（想法一） |

## 六、可做实验（全部纯防御侧）

1. **B 检测实验**：合成账本——注入 k 个伪造 -1 经跨仓边传播，统计 B
   出现率与传播深度（现有 retbridge_fleet 夹具可改造）；
2. **scrubbing 曲线**：verified_ratio 时间序列对注入速率的敏感性（本地
   即可仿真）；
3. **裁决 TMR**：yara-python + trit-re + 第三个引擎对同批样本三票表决，
   量测单引擎投毒被压制的比率（N4 对拍基建直接复用）。

## 七、边界

- 太空辐照与对抗注入的哲学差异（§一）意味着**多数票不是万能迁移**：
  三个被同一攻击者污染的扫描器会一致地投毒——TMR 防单点故障不防合谋。
  合谋防御回到溯源与矛盾检测（想法一），不在表决层。
