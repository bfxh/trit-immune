# BLA 对抗研究：怎么把破解 AI 逆向防御盾的成本压到 10×

> 2026-11-13。对象：morluto/rea（给编码 agent 的逆向工具集，MCP + CLI，
> 覆盖原生二进制/JS/Electron/.NET/APK/WASM/模型工件等 30+ 目标，证据返回式）
> 与 qybaihe/bla（针对 REA 类 agent 的防御盾：**毒饵→耗尽→纠缠→楚门世界**，
> 宣称 300×–2800× token 放大、14/14 运行时等价）。立场：**防御研究**——BLA
> 自带公开 CrackMe 竞技场（v6–v9）明确邀请红队方法验证；本文不针对任何
> 第三方软件，全部机制取自两项目公开文档。

## 一、威胁模型：这两样东西到底在对抗什么

- REA 把"逆向"从手艺变成**对话**：agent 问一句，REA 出伪代码/证据/未知项。
  说明书口径：未防护工件上克隆核心逻辑"几秒、约 $0.20"。
- BLA 的赌注是三件事：①agent 的上下文有限且贵（毒饵与耗尽都打这个）；
  ②agent 信任工具返回的结构合法性（毒饵全格式合法）；③agent 爱走捷径
  （单点 patch、把导出当 oracle——纠缠打这个）。
- 关键事实：BLA 的耗尽全靠 **REA 的实现常数**（`MAX_BUILD_INFO_BYTES`
  1 MiB、ASAR 头 16 MiB、Wabt 表示预算、tshark JSON 8 MiB、
  `primitive-candidates > 256`、模型元数据嵌套 32 层……）——这些阈值
  **写在 REA 的开源代码与 BLA 自己的 README 表格里**。

## 二、打破路径：探针 → 地图 → 换通道 → 动态锚定 → 精读（成本 ≈ 10×）

把 BLA 宣称的 2800× 压到 10× 的最小方法论，五步、每步一次性成本：

### 2.1 预算探针先行（≈1×）——错误消息是免费的配置泄露

不用完整分析 pass 去踩 19+ 颗雷。对每个格式发**最小调用**，REA 返回的
`CapacityError` / `LIMITED` + 预算名（"ASAR header exceeds 16 MiB"、
"primitive-candidates exceeds 256"）就是 BLA 的**防御配置自白**：阈值、
格式、触发条件全在里面。一次探针 pass 建立全格式地雷图，成本 O(格式数)
与样本大小无关。**毒饵与陷阱的排布本身就是情报**——它标记了作者认为
值得保护的位置。

### 2.2 换通道（≈1×）——防的是通道不是内容

BLA 的耗尽全部作用在 **REA 内置解析器的预算壳**上：ASAR 头 16 MiB 挡的
是 REA 的 reader，不是 ASAR 格式。直接调格式原生工具
（`asar extract`、`wasm2wat`、`sqlite3` CLI、Python `marshal`、自写
zstd/tar 解包）绕开包装层——预算常数对一个**不经过 REA 的分析者**不
存在。**推论：实现常数的预算防线，对换通道者失效**（见 §四 定理 2）。

### 2.3 语义惰性检测（≈1×）——毒饵的统一签名

毒饵千姿百态（opaque predicate、蜂蜜 SourceMap、影子状态机、蜜表、
SGX/TPM 假清单），但有一个**统一的结构签名**：

> **格式合法但语义惰性——生产的字节没有任何真实消费路径。**

三个可机判的子签名：
1. **不可达谓词**：数论 opaque predicate（`7x²−1 ≠ y² (mod 7)`）是
   **恒真式**——小规模枚举/符号求值直接判死，成本 O(1)；
2. **零消费者**：从数据/导出点反向追踪读取路径——无消费者的表、映射、
   状态机 = 假数据（BLA 的蜜表按构造没有真实读写路径）；
3. **与动态观测冲突**：跑一次真实输入（用户态——BLA 自认"normal user
   execution untouched"，**楚门只对检测到的调试器撒谎**），录 I/O 与
   状态迁移；静态毒饵与观测行为冲突即标记丢弃。

### 2.4 动态锚定（≈2×）——一锤定音的便宜证据

静态 vs 静态永远打嘴仗（BLA 的毒饵就是为嘴仗设计的）；**行为事实**只
有一条。strace/API hook/抓包一轮，把"程序实际做了什么"锚定下来，之后
所有静态阅读以行为为准绳——毒饵免疫的本质是**给证据分级**：复现 > 静态
声称（这正是 trit-immune catalog 的 `Reproduced > Adjudicated > Claimed`
层级）。

### 2.5 聚焦精读（≈6×）——只在真核上花深度预算

地图 + 通道 + 锚定之后，剩余的真实逻辑面 ≈ 原始未防护面。对它做一次
正常深度分析。合计 ≈ 10×——**BLA 的 2800× 放大率对无地图的蛮干 agent
成立，对带方法论的分析者是常数因子**。

### 2.6 纠缠（Entangle）为什么防得住也防不住

SHA-256 sibling 绑定让"单点 patch / 删毒饵"失效——**防篡改是真防御**
（改一处要重签全家）。但分析者不需要篡改，只需要**理解**；即便要改，
重 seal 的成本 = 按同一清单算一遍哈希（BLA 自己定义了清单结构）。
**防篡改 ≠ 防理解**——这是 BLA 唯一的硬防御，也是最便宜可被复用的。

## 三、楚门世界的裂缝

"Runtime Truman Show"（检测 CDP/Frida/Inspector 后给假遥测）依赖
**检测器**——检测器本身是可探测的代码：
- 它必须区分"用户正常跑"与"调试附加"→ 两者的系统调用/时序/句柄差异
  存在，反向检测检测器（对着差异面 fuzz）是标准手法；
- 假遥测要"可信"就必须与真实实现共享大部分状态 → 真假混合态本身就是
  可检测的不变量（假遥测永远不会导致真实的副作用——副作用差分即真相）。
成本不低（这是 BLA 最硬的一层），但注意它**只保护 Electron 运行时**
一种形态，覆盖面最窄。

## 四、理论化：两条定理 + 一个二分

### 定理 1（毒饵免疫，非形式）

*任何"格式合法但语义惰性"的投毒，在【多源交叉验证 + 动态锚定】下，
识别成本 = O(投毒量)，与被保护程序的分析总量无关；且被识别的毒饵是
高价值情报（标出防御者的保护意图）。*

- 论证：惰性 = 无真实消费路径/与行为观测冲突（§2.3 三签名可机判）；
  交叉验证把"每个毒饵"从"分析成本"变成"一次冲突判定"；冲突判定本身
  产出关于防御者意图的信息。**推论：Poison 支柱对带交叉验证的分析者
  是负资产**——毒越多，地图越好画。
- 这是 trit-immune 模因抗性框架（MEMETIC-RESISTANCE）的攻防镜像：
  TMR 多源表决（单源毒即弃）、`four=B` 矛盾告警（毒与事实冲突 → ⊥）、
  catalog 验证层级（复现证据 > 静态声称）在"检测器 vs 投毒工件"场景的
  直接应用。

### 定理 2（预算对偶，非形式）

*基于分析器实现常数的预算陷阱，其有效性 = 攻击者对该实现的无知程度。
对开源实现（阈值公开）或换通道者（阈值不存在），防线退化为零；
只有"代价外生"的防御——真实计算复杂度（如全程序低解释开销但高分析
复杂度的变换）——对换通道者依然成立。*

- 论证：预算阈值 c 是分析器 P 的属性而非工件 D 的属性；攻击者换掉 P
  即绕开 c。代价外生的防御（比如让语义恢复所需的计算本身不可行）不依赖
  P。**推论：Exhaust 支柱的最稳形态不是"塞爆 REA 的常数"，而是"抬高
  语义恢复的真实复杂度"——后者才是几十年的混淆学（VM/白盒密码）**。
  BLA 选了便宜的那条路（对 agent 有效、对方法论者失效）。

### 二分：老千 vs 硬防御

| 支柱 | 性质 | 对方法论者的效果 |
|---|---|---|
| Poison（毒饵） | 老千——赌对方信 | 识破后**反伤**（免费情报） |
| Exhaust（耗尽） | 老千——赌对方穷且换不了通道 | 换通道/带地图即失效 |
| Entangle（纠缠） | **硬防御**——真实的完整性约束 | 防篡改成立；防理解不成立 |
| Truman（楚门） | 半硬——运行时检测+假遥测 | 覆盖最窄（仅 Electron 运行时），检测器可反向探测 |

**结论：BLA 的护城河只在"对方是蛮干 agent"这个假设上。它最好的遗产
是 Entangle 的完整性纪律与 `bla verify` 的运行时等价测试——这两样是
真贡献；毒饵经济学在对称信息下归零。**

## 五、反哺三线（比它更能防 + 更能攻）

1. **trit-re：诱饵特征检测器（防御侧新规则）**——BLA 形毒饵会**故意
   触发**我们的检测链（canary 里放假的敏感 API 名 → 栈串/dynres/共现
   全中假信号）。已有答案：TMR 多扫描器表决（单源毒即降权 Unknown）+
   needs_review 弃权。新增可做：**读写不平衡分析**（§2.3 签名 2）——
   "高熵 + 格式合法 + 零消费路径" → `decoy_suspect` fact，落弃权而非
   -1；这是"扫描器永不 +1"在投毒对抗下的自然延伸。
2. **证据分级即分析器架构**：把 catalog 的 `Reproduced > Adjudicated >
   Claimed` 提升为逆向 agent 的工作流原语——工具返回分两栏：`facts`
   （动态锚定/多源一致）与 `claims`（静态单源）；LLM 消费时只对
   `claims` 花怀疑预算。REA 的"证据返回"只走了一半（来源标注、无分级）。
3. **对 REA 的对标改进**：预算耗尽时返回**分段建议**（哪 16 MiB 头、
   哪 256 个候选——把失败变成地图）而不是裸 `CapacityError`；这恰好
   是"弃权是可复算输出"论文 C2 的产品化。
4. **可量化的下一步**（需隔离子系统确认，红线照旧）：对 BLA 公开
   CrackMe v6–v9 跑我们的 agent 栈 + §二方法论，实测放大率曲线——
   把 10× 从论证变成读数。
