# 三线安全体系总纲

> 一句话：**三条线、一个账本**——逆向线看清二进制（trit-re），攻击线探明网络面
> （trit-net），账本线裁决一切（trit-immune）。每条线产出三值事实，账本收口，
> 门禁与目录消费。本文是总纲：架构、不变量、方法论、方向库。

## 一、三线架构

```
                    ┌─────────────────────────────┐
                    │   trit-immune 裁决账本       │
                    │   节点=Trit{-1,0,+1}         │
                    │   门禁/目录/传播/CRDT 同步    │
                    └──────────▲──────┬───────────┘
                     retbridge │      │ catalog/family_tasks
                     (JSONL→账本)      │ (方向库/排活)
                    ┌──────────┴──┐   │
                    │ trit-re 逆向 │   │
                    │ triage→JSONL │   │
                    │ N2 CFG/N4 签名│   │
                    └─────────────┘   │
                                      ▼
                    ┌─────────────────────────────┐
                    │   trit-net 攻击面（worktree） │
                    │   pcap→flow→三值弃权判决      │
                    │   calibrate→规则→flow 检测    │
                    │   probe→攻击图→登记桥         │
                    └─────────────────────────────┘
```

- **逆向线**（trit-re）：二进制 → 结构解析 → 三值判定（`Triage`）→ JSONL 台账。
  N2 四层最小 CFG 看清函数边界，N4 两层签名匹配与官方 YARA 对拍。
- **攻击线**（trit-net）：pcap → 双向流 → 三值弃权判决（M0）；分档校准 → 规则
  → flow 检测（M1.6）；受控探测 → 三值攻击图（M2/M3）；漂移门盯基线。
- **账本线**（trit-immune）：所有事实收口为 `Trit` 节点。`retbridge` 把逆向
  JSONL 翻译成账本 Delta；`catalog` 把海产出的发现折叠成族；`family_tasks`
  把族折成有界劳动；门禁（K3 AND）收口放行决策。

## 二、跨线不变量（每条线都要守，违反即 bug）

1. **扫描器永不 +1**：静态分析说"没看见"不等于"安全"。trit-re 的 `false`
   判定不进账本（retbridge 丢掉），trit-net 的 `False` 同理。
2. **弃权是输出不是失败**：证据不足 → `0`（Unknown），不硬猜。
   trit-re 的 X（弃权）、trit-net 的 abstain、trit-immune 的 Unknown 是
   同一件事在三层的名字。
3. **负结果入册**：实测的负结果（良性尾部单独用是负结果、跨日直接失效）
   照实写进文档——负结果是一等公民的知识，不是要藏的失败。
4. **fail-closed**：截断/预算耗尽/解析失败 → `Unknown`/显式 Err，绝不静默
   放行（sigscan 的 `SCAN_BUDGET`、yaraparse 的 `Unsupported`、
   mutation_check 的锚点 0 次）。
5. **可复算**：固定种子、基线 JSON、TSV 导出——同输入必同输出。
6. **高危测试永不进主系统**（用户指令 2026-11-07 固化）：任何攻击性
   实验（逃逸复现/攻击验证/对抗样本）只在隔离子系统（可丢弃 VM、零
   凭据、egress deny-by-default，规格见 AI-ATTACK-SURFACE §四）；对
   当前运行环境不做逃逸尝试或探测。

## 三、方法论：三进制思维如何生成任务

三值不是信仰，是**生成与分诊任务的模式**。四条生成律：

### 律一：断言三值化

每个"对/错"断言追问第三个状态。检测器的输出不是"攻击/正常"而是
"攻击/正常/**弃权**"；规则的结果不是"命中/未命中"而是"命中/未命中/
**不可评估**"（yaraparse 对解析不了的规则判 `Unsupported`→`Unknown`，
绝不静默跳过）。生成任务时问：**我的系统里哪些二元断言藏着一个未处理的
Unknown？** 每找到一个就是一个任务。

### 律二：方向三值分诊

方向库里没有"要做/不做"的二元堆——每个方向 ∈ {`+1` 做、`0` 挂起、
`-1` 不做}，且 **`0` 必须写明解锁条件，`-1` 必须写明理由**。
拒绝无理由的 `-1`（那只是懒惰）和无条件的 `+1`（那只是许愿）。
见 §五方向库。

### 律三：管线三层

感知（pcap/二进制/对话）→ 裁决（三值判定/门禁/折叠）→ 执行（排活/修复/
对外发布）。每层只与相邻层说话。生成任务时问：**我的管线缺哪一层？**
层的边界处（retbridge 的 JSONL→Delta、登记桥的 JSONL→攻击图）就是
任务密集区——跨层数据的翻译与消毒。

### 律四：负结果三问

每个负结果（FPR 14%、跨日失效、良性尾部单独负收益）问三问：
**数据问题**（分布漂移/样本不足）？**方法问题**（STE 梯度估计/特征不足）？
**问题本身问题**（该信号在该任务上不可分）？三问之后方向自动分诊：
数据→等样本；方法→可做；问题本身→`-1` 不做（写明）。

## 四、三线合流的数据流（当前态）

```
逆向：  样本 → triage --jsonl → retbridge → 账本（-1/0，false 丢弃）
            └→ sigscan --rules → 官方 YARA 对拍（MATCH 6/DIFF 0）
攻击：  pcap → flow --rules --band → 三值检测（校准规则回写后）
            └→ probe → 登记桥 → 攻击图（M2 边带证据等级）
账本：  catalog → 族折叠（根因签名）→ verified_ratio（已验证比例）
            └→ family_tasks → 有界劳动（修上游/隔离复核）
```

已闭环的回路（全部有测试钉死）：

| 回路 | 落库 |
|---|---|
| 逆向 JSONL → 账本（false 丢弃=扫描器永不 +1） | trit-immune #51 |
| 校准规则 → flow 检测（校准回写闭环） | trit-net #316 |
| probe 报告 → 攻击图登记桥 | trit-net #313 |
| 发现 → 族折叠 → 排活 | trit-immune #50 |
| 目录 → 对外发布（tiered VEX + attestation） | trit-immune #50 |
